Skyscraper Step Visualizer

Watch a solver place buildings, reject, back up and undo until every clue fits. Pick a solving option (row by row, column by column or brute force), or load a trace from your own solver. Any size from 1×1 to 9×9.

How to read this

The board

Each clue on the edge says how many buildings you can see looking along that row or column from that side. A taller building hides every shorter one behind it. Every row and column holds each height exactly once. New to skyscraper puzzles? You can try one on BrainBashers first.

The counters

  • Accepted: a building was placed and every clue can still be met.
  • Rejected: a placement broke a clue, so it was removed straight away and the solver tries the next option.
  • Dead end: nothing is left to try at this point, so the solver backs up and undoes the placement before it. This is backtracking.

Why the options differ

Row by row and column by column place the tallest buildings first and check the clues after every placement, so a bad choice is caught early. Brute force fills cells one at a time and checks a clue only once its whole row or column is full, so it explores far more dead ends before noticing a mistake.

Try this

  1. Pick a size and an example puzzle, open the Simulation tab and press Step a few times to follow the log.
  2. Press Solve, then look at the depth chart: it shows how far the solver climbed and fell back.
  3. Press Compare all three and see how many steps each option needed.

Clues go in one row, side by side: from the top, from the bottom, from the left, then from the right. Each number is how many buildings you can see looking in from that spot.

How to type the clues

Type one number for every position around the board, separated by spaces. Take the four sides in this order:

  1. From the top: one clue per column, left to right.
  2. From the bottom: one clue per column, left to right.
  3. From the left: one clue per row, top to bottom.
  4. From the right: one clue per row, top to bottom.

Example for a 4×4 board. The arrows show the direction each clue looks, and the small digit is its position on that side.

Use your own solver

Nothing of yours runs here. Your C solver writes a trace of every number it places and removes, and this page replays it with the same board, counters, depth chart and log as the built-in solvers.

Choose a trace file, or drop one anywhere on this page

C helper

Add the two helper files to your project, then make four calls: trace_start(game->size, game->clues) once after parsing, trace_place(row, col, num) and trace_remove(row, col) inside the helpers that write and clear a cell, and trace_end(solved) after solve() returns. Run the program once and it writes skyscraper.trace next to it.

A placement taken out again at once is counted as a rejection, and every other removal as an undo preceded by a dead end. Runs longer than 2,000,000 events show their first part.
